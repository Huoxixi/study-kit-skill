## 实现的管理方式

课程是用户命名的分类，一门课可以收纳多个章节或资料 HTML。每份文件保留独立编号、独立网页存储来源和学习记录；移动或改名分类不改变文件编号。新增或更新学习内容不需要重新制作 APP。

- 一次多选 HTML / HTM；逐份处理，部分文件失败不回滚或丢弃其他成功项，结果区给出数量和错误。
- 新建、重命名课程；将文件归类、移动分类；移除课程分类只将文件放到“未分类”。
- 搜索资料名称、文件名与课程名；按最近学习、最近导入或名称排序；支持置顶、改名和删除单份资料。
- 相同标题不再充当唯一身份。同名不同内容可分别保存；同课程内完全相同的内容提示已有或批量去重。想更新指定文件时，使用“管理 → 更新 HTML”，保持自定名称和学习记录。
- 接受完整独立 HTML、HTM、常见 HTML 片段，以及 UTF-8、带 BOM 的 UTF-16、正确声明 GBK 等编码的网页。展示引擎不依赖人工智能课程的数据结构。
- 完整备份增加课程分类、置顶和原文件名，保留自定名称及全部 localStorage。恢复后切到对应分类，避免资料因当前筛选而不可见。
- 更新 HTML 时若误选完整备份，会拒绝更新并保留现有内容和进度；完整备份应从资料库导入入口恢复。

旧版记录默认在“未分类”。给旧文件设置课程即可，无需再次导入，更不能为升级先卸载应用。

## 范围与限制

- 单份 HTML 最大 20 MiB，一次选择上限 100 份；本次没有执行 100 份或全部最大体积文件的极限负载测试。
- 支持独立网页，不自动导入相邻资源目录、不自动修复依赖服务器的页面，也不把静态 HTML 自动转成卡片或题目。交互功能由文件本身提供。
- 主要保留页面写入的本地存储。没有写入持久存储的临时 DOM 状态，不承诺自动变为长期学习记录。
- 不提供云同步；卸载前应导出备份。仅升级安装会保留原数据，清除应用数据或卸载则不同。
- 没有在物理手机、其他厂商文件管理器、其他 Android 版本或平板上实测。
- 本次 userdebug 系统强制启用底层 WebView 调试，普通生产系统的端口关闭行为仍未实测；正式 manifest 非 debuggable，应用显式调用关闭 API，沿用 R83 的边界。

外部实现依据继续沿用 `docs/外部资料采用记录.md` 的 R76—R83，没有引入新的第三方打包服务或网页模板。
